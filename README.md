# LogLens · 网站访问日志可视化分析工具

一个基于 Flask 的访问日志分析工具：导入 Nginx / Apache `combined` 格式日志，自动完成解析、统计、异常检测与可视化展示。解析和检测均在本地完成，日志不会上传到任何外部服务器。

## 一、功能特性

- **日志导入**：支持上传 `.log` 文件，单文件上限 32 MB，1 万行日志解析流畅。
- **统计分析**：按小时访问趋势、Top 10 来源 IP、Top 10 请求 URL、状态码分布、请求方法分布。
- **异常检测**：基于 JSON 配置规则识别 9 类风险行为，输出风险等级、命中规则与判定依据。
- **可视化**：ECharts 渲染折线图、环形图、柱状图与横向条形图；深色 / 浅色双主题。
- **结果导出**：异常明细一键导出为 CSV（UTF-8 BOM，Excel 可直接打开）。
- **双形态交付**：Flask 完整版 + GitHub Pages 纯前端静态版（`docs/` 目录）。

## 二、技术架构

| 层次 | 实现 |
| --- | --- |
| Web 框架 | Flask 3.1 |
| 日志解析 | `analyzer/parser.py`：正则提取 IP、时间、请求行、状态码、字节数、Referer、UA |
| 统计与检测 | `analyzer/stats.py`：`Counter` 聚合 + 可配置规则引擎 |
| 规则配置 | `rules/rules.json`：关键字、阈值、规则等级集中配置 |
| 路由控制 | `app.py`：上传分析、CSV 导出、演示与压测数据 |
| 前端展示 | ECharts 5.6（本地文件，无 CDN 依赖）+ Jinja2 / 原生 JavaScript |

数据流：上传日志 → 逐行解析 → 统计聚合与规则检测 → 模板渲染 → ECharts 绘图。

## 四、快速开始

```bash
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

浏览器访问 `http://127.0.0.1:5000/`，上传 `.log` 文件即可查看分析结果。

## 五、异常检测规则

规则全部集中在 `rules/rules.json`，可增删关键字、调整阈值而无需改动检测代码。

| 规则 | 等级 | 判定依据 |
| --- | --- | --- |
| 敏感路径探测 | 高危 | URL 命中 `.env`、`.git`、`/admin`、`wp-login`、`phpmyadmin`、`actuator` 等 |
| 注入攻击特征 | 高危 | 带参数请求含 UNION 注入、逻辑注入、目录遍历、XSS、命令执行等载荷（含编码变体） |
| 扫描器 UA | 中危 | UA 含 sqlmap、nikto、nmap、gobuster、curl、python-requests 等工具标识 |
| 可疑请求方法 | 中危 | 出现 PUT / DELETE / TRACE / CONNECT / PATCH |
| 服务端错误 | 中危 | 响应状态码 ≥ 500 |
| 4xx 错误率异常 | 中危 | 单 IP 请求 ≥ 20 且 4xx 占比 ≥ 30% |
| 5xx 错误率异常 | 高危 | 单 IP 请求 ≥ 20 且 5xx 占比 ≥ 5% |
| 疑似目录扫描 | 中危 | 单 IP 累计 ≥ 5 次 404 |
| 高频访问 | 低危 | 单 IP 请求 ≥ 20 且占总请求 ≥ 15% |

单条记录可命中多条规则，记录风险等级取其中最高；规则汇总按规则自身固有等级统计。

## 六、测试结果

### 1. 功能测试

`logs/demo.log`（293 条）：

| 指标 | 结果 |
| --- | --- |
| 解析成功 / 失败 | 293 / 0 |
| 独立 IP / 独立 URL | 12 / 41 |
| 检出异常 | 133 条，综合风险「高危」 |
| 命中规则 | 高频访问 89、扫描器 UA 75、目录扫描 26、敏感路径 24、服务端错误 6、注入特征 5、可疑方法 4、5xx 错误率 3 |

### 2. 万条日志压力测试

`logs/stress_10000.log`（10000 条，1.83 MB）：

| 指标 | 结果 |
| --- | --- |
| HTTP 状态 | 200 |
| 解析 + 检测 + 渲染耗时 | 0.219 秒 |
| 解析失败 | 0 |
| 检出异常 | 414 条 |
| 响应页面大小 | 0.28 MB |

页面只渲染前 100 条明细，统计与检测基于全量数据，因此万条日志下响应体依然很小。

## 七、个人总结

这个课题让我把「日志分析」从概念变成了可运行的工具。实现过程中有三个收获：一是先建立结构化解析层，再往上叠加统计与检测，模块边界清晰，新增规则只需改 JSON 配置；二是异常检测不能只看单条请求，引入 IP 维度聚合后，目录爆破、错误率突增这类"单次无害、量大危险"的行为才能被识别；三是可视化不只是把数字画成图，风险横幅、等级色标和异常明细联动，演示时才能让人快速看懂结论。

压力测试验证了"明细限量渲染"的价值：1 万条日志从上传到返回不到 0.25 秒。目前规则阈值以经验值为主，真实环境还需结合业务基线调优；后续可加入时间窗口滑动统计、IP 信誉比对与规则可视化配置界面。
